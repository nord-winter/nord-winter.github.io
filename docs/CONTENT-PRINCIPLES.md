# Content structure principles

Not design rules, not copy style rules (that's avoid-ai). This is about what goes where and why. Written down because "toporno" placement keeps happening without a checklist to catch it before it ships.

## The checks, before adding or keeping a block

1. **Proof lives next to its claim, never floating alone.** A number on its own ("40%", "80K+ RPS") answers nothing. The same number attached to a specific service, project, or sentence answers "so what." If a stat is not visibly tied to a claim within the same glance, it does not belong.

2. **No repeating the same fact twice on one view without a reason.** If a number already appears attached to something specific further down the same page, an isolated summary of it above is not reinforcement, it is redundant weight. Cut the redundant one, keep the attached one.

3. **One primary action per page.** Every other link or button on that page is visibly secondary (smaller, outlined instead of filled, tucked into a corner tag). If two things compete for the same visual weight, the reader does neither.

4. **Order follows what the reader needs to decide, not what was built most recently.** Default shape: hook, proof, offer, details, how to start. A page with one narrow job (a services page someone already clicked into, a brochure someone already asked for) can skip the hook and start at proof or offer directly, it does not need to re-sell the visit.

5. **A block earns its place by answering a specific reader question at that point in the scroll.** "What do I get," "why trust this," "how do I start," "who is this for." If a block cannot name the question it answers, it is decoration, not content, and decoration that is not honestly labeled as such does not ship (see the site's own standing rule against fake stats).

6. **New sections get proposed before they get built**, with the specific question they answer stated up front, unless already explicitly agreed. Building first and asking after is how redundant blocks like the brochure stats happened.

## How this gets used

Before adding a section: name the reader question it answers in one line. If it duplicates a claim already made elsewhere on the same page, don't add it, or replace the existing one instead of stacking both.

Before a build, a quick self-check pass against this list, the same way a build gets checked for errors before commit.
